# ربات معامله‌گر خودکار صرافی تبدیل

یک ربات پایتونی برای اجرای خودکار استراتژی نوسان‌گیری روی [صرافی تبدیل](https://www.tabdeal.org/) با استفاده از SDK رسمی `tabdeal-python`. ربات نیازی به معرفی دستی نماد ندارد: خودش پرفعالیت‌ترین نمادهای بازار را کشف می‌کند و می‌تواند هم‌زمان روی چند نماد پوزیشن باز داشته باشد.

## ⚠️ هشدار مهم قبل از هر چیز

- **این توصیه مالی نیست.** معامله‌ی خودکار ارز دیجیتال ریسک از دست دادن سرمایه دارد و هیچ استراتژی سودآوری تضمینی ندارد.
- **همیشه اول با `DRY_RUN=true`** (حالت پیش‌فرض) اجرا کنید تا رفتار ربات را روی داده واقعی بازار، بدون ثبت سفارش واقعی، ببینید.
- وقتی به حالت واقعی (`DRY_RUN=false`) رفتید، با **کمترین مبلغ ممکن** شروع کنید.
- کلید API را طوری بسازید که:
  - فقط دسترسی **spot trading** داشته باشد.
  - دسترسی **withdrawal (برداشت)** را **غیرفعال** کنید.
  - اگر صرافی امکان محدودسازی IP را می‌دهد، فعال کنید.
- فایل `.env` را **هرگز** commit یا در جایی به اشتراک نگذارید — شامل کلید و رمز API شماست.

```
tabdeal-trading-bot/

│   ├── strategy.py           # استراتژی‌ها (پیش‌فرض: تقاطع میانگین متحرک)
│   ├── risk_manager.py       # حد ضرر/سود، سقف معامله روزانه، مدار قطع ضرر
│   ├── position.py           # مدل پوزیشن باز
│   └── bot.py                # حلقه اصلی معاملاتی چندنمادی (چند پوزیشن هم‌زمان)
├── scripts/inspect_api.py    # بررسی خروجی خام API قبل از اعتماد به ربات
├── webapp/                   # داشبورد وب محلی (اختیاری، جایگزین main.py)
│   ├── app.py                 # سرور Flask، فقط روی 127.0.0.1
```

## قبل از اجرا: بررسی API با داده واقعی

چون ساختار دقیق پاسخ‌های API تبدیل در مستندات پشت لاگین قرار دارد (docs.tabdeal.org)، قبل از اعتماد به ربات این اسکریپت را اجرا کنید تا مطمئن شوید فرضیات کد (ساختار order book، موجودی حساب، دقت اعشار مقدار سفارش) با پاسخ واقعی هم‌خوانی دارد:

```bash
python scripts/inspect_api.py
```

خروجی را با دقت بررسی کنید، به‌خصوص:
- `exchange_info` برای مطمئن شدن که ساختار فرض‌شده در `src/market_scanner.py` (کلیدهای `tabdealSymbol`/`symbol`، `quoteAsset`، `status`) با پاسخ واقعی هم‌خوانی دارد — و برای پیدا کردن دقت اعشار مجاز (`QUANTITY_PRECISION`) و حداقل مقدار سفارش هر نماد.
- بخش «کشف خودکار watchlist» که نشان می‌دهد ربات با تنظیمات فعلی چه نمادهایی را انتخاب می‌کند.
- `account` برای مطمئن شدن که نام دارایی‌ها (`asset`) با آنچه در `exchange_client.py` فرض شده مطابقت دارد.

## تنظیمات (.env)

| متغیر | توضیح |
|---|---|
| `TABDEAL_API_KEY` / `TABDEAL_API_SECRET` | کلید API (فقط برای حالت واقعی لازم است) |
| `QUOTE_ASSET` | دارایی مبنای بازاری که ربات باید در آن نماد پرفعالیت پیدا کند، مثل `IRT` |
| `WATCHLIST_SIZE` | چند نماد پرفعالیت هم‌زمان زیر نظر گرفته شود |
| `WATCHLIST_REFRESH_MINUTES` | هر چند دقیقه یک‌بار لیست نمادهای پرفعالیت دوباره محاسبه شود |
| `MAX_CONCURRENT_POSITIONS` | حداکثر تعداد پوزیشن باز هم‌زمان (سرمایه درگیر = این عدد × `QUOTE_ORDER_AMOUNT`) |
| `QUOTE_ORDER_AMOUNT` | مبلغ هر معامله بر حسب دارایی quote |
| `QUANTITY_PRECISION` | تعداد رقم اعشار مجاز مقدار سفارش (از exchange_info بگیرید) |
| `STOP_LOSS_PERCENT` | درصد ضرر مجاز قبل از بستن خودکار پوزیشن |
| `TAKE_PROFIT_PERCENT` | درصد سود هدف برای بستن خودکار پوزیشن |
| `MAX_DAILY_LOSS_PERCENT` | سقف ضرر تجمعی روزانه (روی مجموع همه‌ی نمادها)؛ با عبور از آن ربات پوزیشن جدید باز نمی‌کند تا فردا |
| `MAX_TRADES_PER_DAY` | حداکثر تعداد معامله کامل (خرید+فروش) در روز، روی مجموع همه‌ی نمادها |
| `SMA_FAST_PERIOD` / `SMA_SLOW_PERIOD` | دوره‌های میانگین متحرک استراتژی پیش‌فرض (هر نماد نمونه‌ی جدا از استراتژی دارد) |
| `POLL_INTERVAL_SECONDS` | فاصله بررسی قیمت هر نماد (ثانیه) |
| `DRY_RUN` | `true` = فقط شبیه‌سازی، هیچ سفارش واقعی ثبت نمی‌شود |

## اجرا (داشبورد وب محلی)

راه دیگر اجرا، داشبورد تحت وب است که فقط روی سیستم خودتان (`127.0.0.1`) بالا می‌آید — نه یک سایت عمومی. از اونجا می‌تونید کلید API، تنظیمات ریسک و استراتژی رو وارد کنید، ربات رو Start/Stop کنید و لاگ‌ها و وضعیت لحظه‌ای (قیمت، پوزیشن باز، سود/زیان روزانه) رو ببینید.

```bash
cd tabdeal-trading-bot
source venv/bin/activate   # اگر venv نساختید، طبق بخش نصب بسازید
python webapp/app.py
```

بعد در مرورگر خودتان (همون سیستمی که دستور رو زدید) به آدرس زیر برید:

```
http://127.0.0.1:5000
```

### ⚠️ هشدار امنیتی مهم درباره‌ی داشبورد وب

- این سرور **فقط روی 127.0.0.1** (لوکال‌هاست) اجرا می‌شود و از بیرون سیستم شما در دسترس نیست. **هرگز** `host="127.0.0.1"` را در `webapp/app.py` به `0.0.0.0` تغییر ندهید یا این پورت را روی اینترنت/شبکه باز نکنید، مگر اینکه احراز هویت (login) و HTTPS واقعی اضافه کنید — وگرنه هرکسی که به این آدرس برسد می‌تواند کلید API و پول شما را کنترل کند.
- کلید API فقط در فایل `.env` روی همان سیستم ذخیره می‌شود و هیچ‌وقت به مرورگر یا جای دیگری ارسال نمی‌شود.
- این سرور توسعه‌ای Flask است (نه production-grade) و فقط برای استفاده‌ی شخصی و محلی طراحی شده.

## استراتژی پیش‌فرض

استراتژی پیش‌فرض `SmaCrossoverStrategy` (تقاطع میانگین متحرک ساده) در `src/strategy.py` است — فقط یک نمونه‌ی کارکردی ساده برای شروع، نه یک استراتژی بهینه. برای جایگزینی با استراتژی خودتان:

1. در `src/strategy.py` کلاسی بسازید که از `Strategy` ارث‌بری کند و متد `update(self, price: float) -> Signal` را پیاده‌سازی کند.
2. در `main.py` (و `webapp/bot_runner.py` اگر از داشبورد وب استفاده می‌کنید) تابع `strategy_factory` را طوری تغییر دهید که کلاس خودتان را برگرداند. هر نماد یک نمونه‌ی جداگانه از استراتژی می‌گیرد، بنابراین state هر نماد (مثلا میانگین متحرک) از نمادهای دیگر جدا می‌ماند.

## کشف خودکار نماد و چند پوزیشن هم‌زمان

به‌جای این‌که یک نماد ثابت به ربات بدهید، ربات در `src/market_scanner.py`:
1. لیست همه‌ی نمادهای فعال بازار را از `exchange_info` می‌گیرد و بر اساس `QUOTE_ASSET` (مثلا `IRT`) فیلتر می‌کند.
2. بر اساس ارزش آخرین معاملات هر نماد (تقریبی از فعالیت/نقدشوندگی، چون endpoint حجم ۲۴ ساعته در SDK رسمی موجود نیست) پرفعالیت‌ترین‌ها را رتبه‌بندی می‌کند.
3. بالاترین `WATCHLIST_SIZE` نماد را انتخاب و هر `WATCHLIST_REFRESH_MINUTES` دقیقه این لیست را دوباره محاسبه می‌کند.

سپس ربات هم‌زمان روی چند نماد از این لیست پوزیشن باز می‌کند (تا سقف `MAX_CONCURRENT_POSITIONS`). اگر نمادی از لیست خودکار خارج شود ولی پوزیشن باز روی آن دارید، ربات همچنان آن پوزیشن را تا بسته‌شدن (با حد ضرر/سود یا سیگنال فروش) دنبال می‌کند — پوزیشن باز هرگز رها نمی‌شود.

⚠️ **نکته سرمایه:** حداکثر سرمایه‌ای که می‌تواند هم‌زمان درگیر شود تقریبا برابر است با `MAX_CONCURRENT_POSITIONS × QUOTE_ORDER_AMOUNT`. این عدد را متناسب با موجودی واقعی‌تان تنظیم کنید.

## مدیریت ریسک

`RiskManager` سه لایه محافظت دارد (روی مجموع همه‌ی نمادها، نه هرکدام جدا):
1. **حد ضرر/سود روی هر پوزیشن** — بر اساس `STOP_LOSS_PERCENT` / `TAKE_PROFIT_PERCENT`.
2. **سقف تعداد معامله روزانه** — از رفتار بیش‌فعال ربات در بازارهای پرنوسان جلوگیری می‌کند.
3. **مدار قطع ضرر روزانه** — اگر مجموع ضرر روزانه از `MAX_DAILY_LOSS_PERCENT` عبور کند، ربات تا روز بعد پوزیشن جدید باز نمی‌کند (پوزیشن‌های باز موجود همچنان بر اساس حد ضررشان بسته می‌شوند).

به این‌ها `MAX_CONCURRENT_POSITIONS` هم اضافه می‌شود که مستقیما در `bot.py` سقف تعداد پوزیشن هم‌زمان را کنترل می‌کند.

## محدودیت‌های شناخته‌شده

- API تبدیل endpoint مشخصی برای کندل/OHLCV یا حجم ۲۴ ساعته در SDK رسمی ندارد؛ قیمت از `depth` (میانگین بهترین خرید/فروش) یا در صورت خطا از آخرین معامله (`trades`) خوانده می‌شود، و رتبه‌بندی «پرفعالیت‌ترین نمادها» هم یک تقریب بر اساس ارزش آخرین چند معامله است، نه حجم واقعی ۲۴ ساعته.
- اگر فیلد‌های واقعی `exchange_info` با فرض‌های `src/market_scanner.py` فرق داشته باشد (کلید نماد، quote asset، status)، کشف خودکار ممکن است لیست خالی یا نادرست برگرداند و به لیست پیش‌فرض (`BTC_IRT, ETH_IRT, USDT_IRT`) سقوط کند — حتما اول با `scripts/inspect_api.py` بررسی کنید.
- استراتژی پیش‌فرض ساده است و برای معاملات واقعی باید بک‌تست و تنظیم شود.
- این پروژه backtest ندارد؛ قبل از اجرای واقعی، منطق استراتژی را جداگانه روی داده تاریخی محک بزنید.
- بررسی سیگنال چند نماد در هر چرخه به‌صورت متوالی (نه موازی) انجام می‌شود؛ اگر `WATCHLIST_SIZE` را خیلی زیاد کنید، ممکن است یک چرخه کامل بیشتر از `POLL_INTERVAL_SECONDS` طول بکشد.
