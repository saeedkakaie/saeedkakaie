# ربات معامله‌گر خودکار صرافی تبدیل

یک ربات پایتونی برای اجرای خودکار استراتژی نوسان‌گیری روی [صرافی تبدیل](https://www.tabdeal.org/) با استفاده از SDK رسمی `tabdeal-python`.

## ⚠️ هشدار مهم قبل از هر چیز

- **این توصیه مالی نیست.** معامله‌ی خودکار ارز دیجیتال ریسک از دست دادن سرمایه دارد و هیچ استراتژی سودآوری تضمینی ندارد.
- **همیشه اول با `DRY_RUN=true`** (حالت پیش‌فرض) اجرا کنید تا رفتار ربات را روی داده واقعی بازار، بدون ثبت سفارش واقعی، ببینید.
- وقتی به حالت واقعی (`DRY_RUN=false`) رفتید، با **کمترین مبلغ ممکن** شروع کنید.
- کلید API را طوری بسازید که:
  - فقط دسترسی **spot trading** داشته باشد.
  - دسترسی **withdrawal (برداشت)** را **غیرفعال** کنید.
  - اگر صرافی امکان محدودسازی IP را می‌دهد، فعال کنید.
- فایل `.env` را **هرگز** commit یا در جایی به اشتراک نگذارید — شامل کلید و رمز API شماست.

## ساختار پروژه

```
tabdeal-trading-bot/
├── main.py                  # نقطه ورود اجرای ربات
├── src/
│   ├── config.py             # خواندن تنظیمات از .env
│   ├── exchange_client.py    # لایه ارتباط با API تبدیل (قیمت، موجودی، سفارش)
│   ├── strategy.py           # استراتژی‌ها (پیش‌فرض: تقاطع میانگین متحرک)
│   ├── risk_manager.py       # حد ضرر/سود، سقف معامله روزانه، مدار قطع ضرر
│   ├── position.py           # مدل پوزیشن باز
│   └── bot.py                # حلقه اصلی معاملاتی
├── scripts/inspect_api.py    # بررسی خروجی خام API قبل از اعتماد به ربات
└── tests/                    # تست‌های واحد (بدون نیاز به اتصال اینترنت)
```

## قبل از اجرا: بررسی API با داده واقعی

چون ساختار دقیق پاسخ‌های API تبدیل در مستندات پشت لاگین قرار دارد (docs.tabdeal.org)، قبل از اعتماد به ربات این اسکریپت را اجرا کنید تا مطمئن شوید فرضیات کد (ساختار order book، موجودی حساب، دقت اعشار مقدار سفارش) با پاسخ واقعی هم‌خوانی دارد:

```bash
python scripts/inspect_api.py
```

خروجی را با دقت بررسی کنید، به‌خصوص:
- `exchange_info` برای پیدا کردن دقت اعشار مجاز (`QUANTITY_PRECISION` در `.env`) و حداقل مقدار سفارش برای نماد خودتان.
- `account` برای مطمئن شدن که نام دارایی‌ها (`asset`) با آنچه در `exchange_client.py` فرض شده مطابقت دارد.

## تنظیمات (.env)

| متغیر | توضیح |
|---|---|
| `TABDEAL_API_KEY` / `TABDEAL_API_SECRET` | کلید API (فقط برای حالت واقعی لازم است) |
| `SYMBOL` | نماد معاملاتی، مثل `BTC_IRT` |
| `QUOTE_ORDER_AMOUNT` | مبلغ هر معامله بر حسب دارایی quote |
| `QUANTITY_PRECISION` | تعداد رقم اعشار مجاز مقدار سفارش (از exchange_info بگیرید) |
| `STOP_LOSS_PERCENT` | درصد ضرر مجاز قبل از بستن خودکار پوزیشن |
| `TAKE_PROFIT_PERCENT` | درصد سود هدف برای بستن خودکار پوزیشن |
| `MAX_DAILY_LOSS_PERCENT` | سقف ضرر تجمعی روزانه؛ با عبور از آن ربات متوقف می‌شود تا فردا |
| `MAX_TRADES_PER_DAY` | حداکثر تعداد معامله کامل (خرید+فروش) در روز |
| `SMA_FAST_PERIOD` / `SMA_SLOW_PERIOD` | دوره‌های میانگین متحرک استراتژی پیش‌فرض |
| `POLL_INTERVAL_SECONDS` | فاصله بررسی قیمت (ثانیه) |
| `DRY_RUN` | `true` = فقط شبیه‌سازی، هیچ سفارش واقعی ثبت نمی‌شود |

## استراتژی پیش‌فرض

استراتژی پیش‌فرض `SmaCrossoverStrategy` (تقاطع میانگین متحرک ساده) در `src/strategy.py` است — فقط یک نمونه‌ی کارکردی ساده برای شروع، نه یک استراتژی بهینه. برای جایگزینی با استراتژی خودتان:

1. در `src/strategy.py` کلاسی بسازید که از `Strategy` ارث‌بری کند و متد `update(self, price: float) -> Signal` را پیاده‌سازی کند.
2. در `main.py` به‌جای `SmaCrossoverStrategy(...)` کلاس خودتان را نمونه‌سازی کنید.

## مدیریت ریسک

`RiskManager` سه لایه محافظت دارد:
1. **حد ضرر/سود روی هر پوزیشن** — بر اساس `STOP_LOSS_PERCENT` / `TAKE_PROFIT_PERCENT`.
2. **سقف تعداد معامله روزانه** — از رفتار بیش‌فعال ربات در بازارهای پرنوسان جلوگیری می‌کند.
3. **مدار قطع ضرر روزانه** — اگر مجموع ضرر روزانه از `MAX_DAILY_LOSS_PERCENT` عبور کند، ربات تا روز بعد پوزیشن جدید باز نمی‌کند (پوزیشن‌ها همچنان بر اساس حد ضررشان بسته می‌شوند).

## محدودیت‌های شناخته‌شده

- API تبدیل endpoint مشخصی برای کندل/OHLCV در SDK رسمی ندارد؛ قیمت از `depth` (میانگین بهترین خرید/فروش) یا در صورت خطا از آخرین معامله (`trades`) خوانده می‌شود.
- استراتژی پیش‌فرض ساده است و برای معاملات واقعی باید بک‌تست و تنظیم شود.
- این پروژه backtest ندارد؛ قبل از اجرای واقعی، منطق استراتژی را جداگانه روی داده تاریخی محک بزنید.
