# ربات معامله‌گر خودکار صرافی تبدیل

یک ربات پایتونی برای اجرای خودکار استراتژی نوسان‌گیری روی [صرافی تبدیل](https://www.tabdeal.org/) با استفاده از SDK رسمی `tabdeal-python`. ربات نیازی به معرفی دستی نماد ندارد: خودش پرفعالیت‌ترین نمادهای بازار را کشف می‌کند و می‌تواند هم‌زمان روی چند نماد پوزیشن باز داشته باشد.

## ⚠️ هشدار مهم قبل از هر چیز

- **این توصیه مالی نیست.** معامله‌ی خودکار ارز دیجیتال ریسک از دست دادن سرمایه دارد و هیچ استراتژی سودآوری تضمینی ندارد.
- **همیشه اول با `DRY_RUN=true`** (حالت پیش‌فرض) اجرا کنید تا رفتار ربات را روی داده واقعی بازار، بدون ثبت سفارش واقعی، ببینید.
- وقتی به حالت واقعی (`DRY_RUN=false`) رفتید، با **کمترین مبلغ ممکن** شروع کنید.
- کلید API را طوری بسازید که:
  - فقط دسترسی **spot trading** داشته باشد.
  - دسترسی **withdrawal (برداشت)** را **غیرفعال** کنید.
  - اگر صرافی امکان محدودسازی IP را می‌دهد، فعال کنید.
- فایل `.env` را **هرگز** commit یا در جایی به اشتراک نگذارید — شامل کلید و رمز API شماست.

## قبل از اجرا: بررسی API با داده واقعی

چون ساختار دقیق پاسخ‌های API تبدیل در مستندات پشت لاگین قرار دارد (docs.tabdeal.org)، قبل از اعتماد به ربات این اسکریپت را اجرا کنید تا مطمئن شوید فرضیات کد (ساختار order book، موجودی حساب، دقت اعشار مقدار سفارش) با پاسخ واقعی هم‌خوانی دارد:

```bash
python scripts/inspect_api.py
```

خروجی را با دقت بررسی کنید، به‌خصوص:
- `exchange_info` برای مطمئن شدن که ساختار فرض‌شده در `src/market_scanner.py` (کلیدهای `tabdealSymbol`/`symbol`، `quoteAsset`، `status`) با پاسخ واقعی هم‌خوانی دارد — و برای پیدا کردن دقت اعشار مجاز (`QUANTITY_PRECISION`) و حداقل مقدار سفارش هر نماد.
- بخش «کشف خودکار watchlist» که نشان می‌دهد ربات با تنظیمات فعلی چه نمادهایی را انتخاب می‌کند.
- `account` برای مطمئن شدن که نام دارایی‌ها (`asset`) با آنچه در `exchange_client.py` فرض شده مطابقت دارد.

## تنظیمات (.env)

| متغیر | توضیح |
|---|---|
| `TABDEAL_API_KEY` / `TABDEAL_API_SECRET` | کلید API (فقط برای حالت واقعی لازم است) |
| `QUOTE_ASSET` | دارایی مبنای بازاری که ربات باید در آن نماد پرفعالیت پیدا کند، مثل `IRT` |
| `QUANTITY_PRECISION` | دقت اعشار پیش‌فرض (fallback)؛ ربات برای هر نماد جداگانه سعی می‌کند دقت واقعی را خودش از exchange_info بخواند (پایین‌تر توضیح داده شده) |
| `TRADING_FEE_PERCENT` | کارمزد هر پای معامله به درصد؛ در محاسبه سود/زیان دو برابرش (خرید+فروش) کم می‌شود. نرخ واقعی حساب خودتان را از تبدیل بگیرید |
| `STOP_LOSS_PERCENT` / `TAKE_PROFIT_PERCENT` | فقط وقتی استراتژی نتواند حد ضرر/سود پویا محاسبه کند استفاده می‌شوند (fallback) |
| `MAX_DAILY_LOSS_PERCENT` | سقف ضرر تجمعی روزانه (روی مجموع همه‌ی نمادها، پس از کسر کارمزد)؛ با عبور از آن ربات پوزیشن جدید باز نمی‌کند تا فردا — تنها مرز ایمنی باقی‌مانده در کنار حد ضرر/سود هر پوزیشن |
| `SMA_FAST_PERIOD` / `SMA_SLOW_PERIOD` | فقط برای استراتژی جایگزین `SmaCrossoverStrategy` استفاده می‌شوند |
| `NEWS_ENABLED` / `NEWS_API_KEY` / `NEWS_CACHE_MINUTES` | فیلتر سبک اخبار (اختیاری، `NEWS_API_KEY` هم اختیاری) — پایین‌تر توضیح داده شده |
| `POLL_INTERVAL_SECONDS` | فاصله بررسی قیمت هر نماد (ثانیه) |
| `DRY_RUN` | `true` = فقط شبیه‌سازی، هیچ سفارش واقعی ثبت نمی‌شود |

⚠️ **دیگر تعداد نماد زیر نظر، بازه بروزرسانی این لیست، مبلغ هر معامله، سقف پوزیشن هم‌زمان و سقف معامله در روز به‌صورت دستی تنظیم نمی‌شوند.** ربات با اختیار کامل این‌ها را خودش تصمیم می‌گیرد (جزئیات در بخش «کشف خودکار نماد و تخصیص سرمایه» پایین‌تر) — یعنی ممکن است در شرایط قوی کل موجودی آزادتان را روی یک کوین بگذارد.

## اجرا (داشبورد وب محلی)

راه دیگر اجرا، داشبورد تحت وب است که فقط روی سیستم خودتان (`127.0.0.1`) بالا می‌آید — نه یک سایت عمومی. از اونجا می‌تونید کلید API، تنظیمات ریسک و استراتژی رو وارد کنید، ربات رو Start/Stop کنید، و این‌ها رو ببینید:
- جدول لحظه‌ای هر نماد: قیمت (به تومان با جداکننده هزارگان)، سیگنال (رنگی: سبز=BUY، قرمز=SELL، خاکستری=HOLD)، پوزیشن باز، هدف فروش/حد ضرر، و سود/زیان (درصد + مبلغ، پس از کارمزد).
- کارت «موجودی حساب» با دکمه بروزرسانی — موجودی هر دارایی را جدا از تبدیل می‌خواند.
- کارت «عملکرد معاملات» با آمار امروز/این‌ماه/امسال.
- لاگ زنده.

```bash
cd tabdeal-trading-bot
source venv/bin/activate   # اگر venv نساختید، طبق بخش نصب بسازید
python webapp/app.py
```

روی گوشی با Termux، به‌جای دستور بالا از `run.sh` استفاده کنید — این اسکریپت قبل از بالا آوردن سرور خودش `termux-wake-lock` را هم فعال می‌کند تا اندروید وسط کار ربات را نکشد:

```bash
bash run.sh
```

بعد در مرورگر خودتان (همون سیستمی که دستور رو زدید) به آدرس زیر برید:

```
http://127.0.0.1:5000
```

### ⚠️ هشدار امنیتی مهم درباره‌ی داشبورد وب

- این سرور **فقط روی 127.0.0.1** (لوکال‌هاست) اجرا می‌شود و از بیرون سیستم شما در دسترس نیست. **هرگز** `host="127.0.0.1"` را در `webapp/app.py` به `0.0.0.0` تغییر ندهید یا این پورت را روی اینترنت/شبکه باز نکنید، مگر اینکه احراز هویت (login) و HTTPS واقعی اضافه کنید — وگرنه هرکسی که به این آدرس برسد می‌تواند کلید API و پول شما را کنترل کند.
- کلید API فقط در فایل `.env` روی همان سیستم ذخیره می‌شود و هیچ‌وقت به مرورگر یا جای دیگری ارسال نمی‌شود.
- این سرور توسعه‌ای Flask است (نه production-grade) و فقط برای استفاده‌ی شخصی و محلی طراحی شده.

## شروع کاملا خودکار (بدون هیچ کاری از طرف شما)

اگر می‌خواهید بعد از تنظیم اولیه دیگر هیچ‌وقت لازم نباشد دستی چیزی بزنید — نه دکمه «شروع» در داشبورد، نه اجرای دستی سرور بعد از ری‌استارت گوشی — دو قابلیت زیر با هم این را می‌دهند:

1. **`AUTO_START=true`** در `.env` (یا تیک «شروع کاملا خودکار» در داشبورد): هر بار که خودِ سرور وب بالا بیاید (`python webapp/app.py` یا `run.sh`)، ربات را بدون نیاز به کلیک روی «شروع» خودش راه می‌اندازد.
2. **بالا آمدن خودکار سرور موقع روشن شدن گوشی** (Termux): اپ [Termux:Boot](https://f-droid.org/packages/com.termux.boot/) را از F-Droid نصب کنید (از Google Play کار نمی‌کند)، یک‌بار بازش کنید تا اجازه‌ی اجرای بعد از بوت را بدهد، بعد:
   ```bash
   mkdir -p ~/.termux/boot
   cp scripts/termux-boot.sh ~/.termux/boot/start-tabdeal-bot.sh
   chmod +x ~/.termux/boot/start-tabdeal-bot.sh
   ```
   اگر مسیر پروژه‌تان `~/tabdeal-trading-bot` نیست، متغیر `PROJECT_DIR` داخل این اسکریپت را اصلاح کنید.

با این دو، از این به بعد با هر روشن/ری‌استارت شدن گوشی: اندروید Termux:Boot را اجرا می‌کند → آن اسکریپت `termux-wake-lock` را می‌گیرد و سرور را بالا می‌آورد → چون `AUTO_START=true` است، ربات هم خودش شروع به معامله می‌کند — کاملا بدون دخالت شما.

⚠️ فقط وقتی این را فعال کنید که از تنظیمات ریسک، `DRY_RUN`/`LIVE` بودن، و کلید API مطمئن هستید؛ چون دیگر یک لحظه‌ی «کلیک آگاهانه‌ی شروع» بین شما و معامله‌ی واقعی وجود ندارد.

### مقاومت در برابر کرش غیرمنتظره

اگر ربات به‌خاطر یک خطای واقعا غیرمنتظره (نه خطاهای معمول شبکه/صرافی که خودش هر چرخه می‌گیرد و لاگ می‌کند و ادامه می‌دهد) متوقف شود، دیگر منتظر کلیک دستی شما نمی‌ماند: ترد پس‌زمینه‌ی داشبورد ۳۰ ثانیه صبر می‌کند و خودش دوباره همان ربات (با همان پوزیشن‌های باز و watchlist، نه از صفر) را ادامه می‌دهد. این تلاش تا وقتی خودتان دکمه «توقف» را نزنید ادامه دارد.

## استراتژی پیش‌فرض: TechnicalStrategy

استراتژی پیش‌فرض (`TechnicalStrategy` در `src/strategy.py`) هفت اندیکاتور تکنیکال را ترکیب می‌کند و فقط وقتی اکثریت هم‌جهت باشند سیگنال می‌دهد:

- **RSI** (اشباع خرید/فروش)
- **MACD** (شتاب روند)
- **باند بولینگر** (نزدیکی قیمت به کف/سقف نوسان اخیر)
- **Stochastic Oscillator**
- **روند EMA بلندمدت** (فیلتر جهت کلی بازار)
- **ابر ایچیموکو (Ichimoku)**: تقاطع Tenkan-sen/Kijun-sen به‌همراه موقعیت قیمت نسبت به ابر Kumo (Senkou Span A/B) — فقط وقتی هر دو هم‌جهت باشند رأی می‌دهد، نه فقط یکی
- **مومنتوم/Rate of Change کوتاه‌مدت**: برخلاف RSI/MACD که خودشان هموارسازی دارند، مستقیم شتاب اخیر قیمت را اندازه می‌گیرد — برای موتور نوسان‌گیری که باید حرکت لحظه‌ای بازار را زود تشخیص دهد مکمل خوبی است

هر اندیکاتور یک رأی ۱-/۰/۱+ می‌دهد؛ فقط با عبور مجموع رأی‌ها از آستانه (پیش‌فرض ۴ از ۷) و فقط روی همان لحظه‌ی عبور (نه هر تیک) سیگنال BUY/SELL صادر می‌شود. همین مجموع رأی‌ها مبنای `confidence()` هم هست که در تخصیص سرمایه بین چند سیگنال هم‌زمان استفاده می‌شود (بخش «کشف خودکار نماد و تخصیص سرمایه» پایین‌تر).

⚠️ چون API تبدیل کندل/OHLC واقعی نمی‌دهد، Tenkan-sen/Kijun-sen/ابر ایچیموکو (که طبق فرمول استاندارد باید از بالاترین/پایین‌ترین *قیمت* هر بازه محاسبه شوند) از همان سری قیمت لحظه‌ای poll‌شده تقریب زده می‌شوند، نه از کندل واقعی؛ و آستانه‌ی مومنتوم (`ROC_THRESHOLD_PERCENT`) ممکن است لازم باشد متناسب با نوسان معمول نمادهایی که معامله می‌کنید تنظیم شود.

⚠️ **درباره‌ی آستانه‌ی ۴ از ۷:** سه اندیکاتور اول (RSI، باند بولینگر، Stochastic) طبیعتا contrarian هستند (فقط در اشباع فروش رأی خرید می‌دهند)، در حالی که چهارتای بعدی (MACD، روند، ایچیموکو، مومنتوم) دنبال‌کننده‌ی روند هستند. این یعنی اگر هر چهار اندیکاتور دنبال‌کننده‌ی روند هم‌زمان هم‌جهت شوند، بدون کمک contrarianها هم به آستانه می‌رسد — پس این استراتژی با ۷ اندیکاتور، نسبت به نسخه‌ی قبلی با ۵ اندیکاتور (که آستانه‌اش ۳ از ۵ بود)، به‌طور محسوسی فعال‌تر/زودتر سیگنال می‌دهد، نه فقط دقیق‌تر. اگر می‌خواهید محافظه‌کارتر باشد، `CONFLUENCE_THRESHOLD` را در `src/strategy.py` بالاتر ببرید (و `NEWS_BOOSTED_THRESHOLD` را متناسب یکی کمتر نگه دارید)؛ فقط قبلش با یک شبیه‌سازی مثل بالا (یا صرفا DRY_RUN طولانی) مطمئن شوید عدد جدید اصلا سیگنالی تولید می‌کند — همان‌طور که آستانه‌ی ۵ از ۷ در آزمایش عملا هیچ‌وقت رأی نمی‌آورد.

**حد ضرر/سود پویا:** چون API تبدیل کندل نمی‌دهد و ATR واقعی در دسترس نیست، حد ضرر/سود هر پوزیشن از نوسان اخیر قیمت (انحراف معیار بازده‌ها) محاسبه می‌شود — نه یک درصد ثابت. این عدد در لحظه‌ی باز شدن پوزیشن قفل می‌شود و در لاگ و داشبورد («هدف فروش / حد ضرر») نمایش داده می‌شود، یعنی همون لحظه‌ی خرید می‌دونید تا چه قیمتی نگه دارید و در چه قیمتی می‌فروشد.

**فیلتر خبر (اختیاری):** اگر `NEWS_ENABLED=true` باشد، ربات قبل از هر خرید عنوان آخرین اخبار همان کوین را از endpoint عمومی و رایگان [CryptoCompare](https://min-api.cryptocompare.com/data/v2/news/) می‌خواند — **بدون نیاز به ثبت‌نام یا کلید**. عنوان‌ها با چند کلیدواژه‌ی ساده (مثل hack/lawsuit در برابر partnership/listing) امتیازدهی می‌شوند. خبر بسیار منفی جلوی خرید را می‌گیرد؛ خبر بسیار مثبت آستانه‌ی خرید را کمی پایین می‌آورد. فروش هیچ‌وقت به‌خاطر خبر متوقف نمی‌شود (مدیریت ریسک همیشه باید بتواند پوزیشن را ببندد). اگر بعدا خواستید محدودیت نرخ بالاتری داشته باشید، یک کلید اختیاری از [cryptocompare.com](https://www.cryptocompare.com/cryptopian/api-keys) در `NEWS_API_KEY` بگذارید — کاملا اختیاری است.

⚠️ این استراتژی هم یک نمونه‌ی معقول برای شروع است، نه توصیه‌ی مالی و نه تضمین سود. حتما قبل از استفاده‌ی واقعی رفتارش را در DRY_RUN زیر نظر بگیرید.

برای جایگزینی با استراتژی خودتان:
1. در `src/strategy.py` کلاسی بسازید که از `Strategy` ارث‌بری کند و متد `update(self, price: float) -> Signal` را پیاده‌سازی کند (و اختیاری: `suggested_risk_levels()` برای حد ضرر/سود پویا).
2. در `main.py` (و `webapp/bot_runner.py` اگر از داشبورد وب استفاده می‌کنید) تابع `strategy_factory(symbol)` را طوری تغییر دهید که کلاس خودتان را برگرداند. هر نماد یک نمونه‌ی جداگانه از استراتژی می‌گیرد، بنابراین state هر نماد از نمادهای دیگر جدا می‌ماند.

## کارمزد و عملکرد معاملات

- `TRADING_FEE_PERCENT` نرخ کارمزد هر پای معامله است؛ در محاسبه‌ی سود/زیان هر پوزیشن، دو برابر این عدد (خرید + فروش) از سود خام کم می‌شود — هم در نمایش زنده‌ی پوزیشن باز، هم در ثبت نهایی معامله.
- هر معامله‌ی بسته‌شده در `data/trade_history.jsonl` ثبت می‌شود (این فایل شخصی‌ست و در `.gitignore` قرار دارد، commit نمی‌شود).
- داشبورد وب کارت «عملکرد معاملات» را نشان می‌دهد: تعداد معامله، درصد و مبلغ سود/زیان برای امروز، این ماه و امسال.
- ⚠️ این درصدها **مجموع ساده‌ی درصد سود/زیان هر معامله** در آن دوره است، نه بازده مرکب یا وزن‌دار سرمایه (مثل بازده واقعی پرتفوی). برای یک ابزار شخصی سبک کافی است ولی معادل محاسبات دقیق مالی نیست.

## کشف خودکار نماد و تخصیص سرمایه

به‌جای این‌که یک نماد ثابت به ربات بدهید، ربات در `src/market_scanner.py`:
1. لیست همه‌ی نمادهای فعال بازار را از `exchange_info` می‌گیرد و بر اساس `QUOTE_ASSET` (مثلا `IRT`) فیلتر می‌کند.
2. بر اساس ارزش آخرین معاملات هر نماد (تقریبی از فعالیت/نقدشوندگی، چون endpoint حجم ۲۴ ساعته در SDK رسمی موجود نیست) پرفعالیت‌ترین‌ها را رتبه‌بندی می‌کند.
3. بالاترین نمادها را تا یک سقف منطقی (پیش‌فرض ۴۰ نماد، ثابت در `market_scanner.DEFAULT_WATCHLIST_SIZE` — چون هرچه نماد بیشتر باشد هر چرخه کندتر می‌شود و ریسک rate limit بالاتر می‌رود) انتخاب می‌کند و هر ساعت (`TradingBot.WATCHLIST_REFRESH_MINUTES` در `src/bot.py`) خودش این لیست را دوباره محاسبه می‌کند — این بازه هم دیگر تنظیم دستی نیست.

اگر نمادی از لیست خودکار خارج شود ولی پوزیشن باز روی آن دارید، ربات همچنان آن پوزیشن را تا بسته‌شدن (با حد ضرر/سود یا سیگنال فروش) دنبال می‌کند — پوزیشن باز هرگز رها نمی‌شود.

**تخصیص سرمایه کاملا خودکار و متناسب با قدرت سیگنال:** در هر چرخه، اگر یک یا چند نماد هم‌زمان سیگنال خرید بدهند، ربات موجودی آزاد `QUOTE_ASSET` را (منهای حاشیه ایمنی ۵٪ — `TradingBot.ALLOCATION_SAFETY_MARGIN`) متناسب با قدرت هر سیگنال (`confidence`، برگرفته از تعداد اندیکاتورهای هم‌جهت در `TechnicalStrategy`) بین آن‌ها تقسیم می‌کند. اگر فقط یک نماد سیگنال بدهد، ممکن است **کل موجودی آزاد** را به همان یک کوین اختصاص دهد. تنها سفارش‌هایی رد می‌شوند که سهم محاسبه‌شده‌شان از یک حداقل فنی (`TradingBot.MIN_ORDER_VALUE`، ۱۰٬۰۰۰) کمتر باشد — نه یک سقف ریسک دستی.

⚠️ چون SDK رسمی فقط سفارش MARKET بر اساس `quantity` (مقدار دارایی مبنا) را پشتیبانی می‌کند، نه مبلغ quote، مقدار سفارش از قیمت لحظه‌ای که خودمان خوانده‌ایم محاسبه می‌شود؛ اگر قیمت واقعی بین این محاسبه و ثبت سفارش کمی حرکت کند، ممکن است سفارش با خطای «موجودی کافی نیست» رد شود — حاشیه‌ی ۵٪ برای همین است. اگر یک نماد در یک چرخه به همین دلیل رد شود، بقیه‌ی نمادهای همان چرخه همچنان امتحان می‌شوند (رد شدن یکی، بقیه را متوقف نمی‌کند).

⚠️ **نکته سرمایه:** دیگر سقف دستی تعداد پوزیشن هم‌زمان یا مبلغ هر معامله وجود ندارد؛ محدودیت واقعی همان موجودی آزادتان است. وقتی موجودی صرف پوزیشن‌های باز شود، به‌طور طبیعی جایی برای پوزیشن جدید نمی‌ماند — نه یک شمارنده‌ی ثابت. این یعنی ریسک تمرکز کامل سرمایه روی یک یا چند کوین واقعی است؛ اگر نمی‌خواهید این‌طور باشد، بخشی از موجودی `QUOTE_ASSET` حساب خودتان را از قبل جدا نگه دارید (ربات فقط به موجودی آزاد دسترسی دارد).

### دقت اعشار مقدار سفارش، جداگانه برای هر نماد

هر بار که watchlist بروزرسانی می‌شود، ربات با `fetch_quantity_precisions` (در `src/market_scanner.py`) تلاش می‌کند دقت اعشار مجاز مقدار (quantity) **هر نماد را جداگانه** از `exchange_info` استخراج کند (اول فیلدهای مستقیم مثل `baseAssetPrecision`، بعد `stepSize` داخل فیلتر `LOT_SIZE`). اگر برای نمادی پیدا نشود، از `QUANTITY_PRECISION` به‌عنوان مقدار پیش‌فرض همان یک نماد استفاده می‌شود — نه اینکه یک عدد ثابت به‌زور روی همه‌ی نمادها اعمال شود. برای دیدن دقیقاً چه عددی برای هر کوین در watchlist فعلی‌تان محاسبه شده:

```bash
python scripts/inspect_api.py
```

## پایداری پوزیشن‌های باز در برابر ری‌استارت

پوزیشن‌های باز در `data/open_positions.json` ذخیره می‌شوند و با هر شروع ربات دوباره خوانده می‌شوند. این برای این است که اگر پردازش به هر دلیل (آپدیت کد، ری‌استارت گوشی، کشته‌شدن Termux توسط اندروید) دوباره اجرا شود، ربات پوزیشن‌های واقعاً بازش را فراموش نکند — وگرنه حد ضرر/سود آن پوزیشن‌ها دیگر چک نمی‌شود و ربات بدون خبر از موجودی واقعا درگیرشده، ممکن است دوباره روی همان دارایی‌ها سرمایه تخصیص دهد.

⚠️ **این فقط پوزیشن‌هایی را دنبال می‌کند که خودِ ربات (بعد از این نسخه) باز کرده باشد.** اگر قبل از این تغییر، به‌خاطر همین باگ چند بار ری‌استارت شده و چند دارایی مختلف خریده باشید، آن‌ها در `data/open_positions.json` ثبت نشده‌اند و ربات حد ضرر/سودی برایشان چک نمی‌کند. باید خودتان از اپ تبدیل تصمیم بگیرید با آن‌ها چیکار کنید (نگه‌داشتن دستی یا فروش دستی)؛ ربات به‌صورت خودکار آن‌ها را نمی‌فروشد یا «قبضه» نمی‌کند.

**مقدار پوزیشن، همیشه در برابر موجودی واقعی چک می‌شود:** مقدار ثبت‌شده در یک پوزیشن ممکن است کمی از موجودی آزاد واقعی دارایی بیشتر باشد (مثلا اگر کارمزد خرید مستقیم از همان دارایی کسر شده باشد). برای همین `sell_market` قبل از هر فروش واقعی، موجودی آزاد واقعی همان دارایی را از تبدیل می‌خواند و اگر از مقدار ثبت‌شده کمتر بود، همان مقدار واقعی را می‌فروشد — نه عدد ذخیره‌شده در `open_positions.json` را — تا سفارش با خطای «موجودی کافی نیست» رد نشود. همین مقدار (چه از موجودی واقعی گرفته شده باشد چه از پوزیشن)، و همچنین مقدار خرید بعد از کسر کارمزد، همیشه قبل از ارسال سفارش به پایین به دقت اعشار مجاز همان نماد گرد می‌شود — وگرنه صرافی سفارش را با خطای «دقت اعشار مقدار رعایت نشده» رد می‌کند.

## مدیریت ریسک

ربات با اختیار کامل تصمیم می‌گیرد چه بخرد، چقدر بخرد و چند پوزیشن هم‌زمان باز کند — بدون سقف دستی تعداد پوزیشن، مبلغ هر معامله یا تعداد معامله در روز. تنها دو لایه محافظت باقی مانده:

1. **حد ضرر/سود روی هر پوزیشن** — پویا، بر اساس نوسان اخیر قیمت همان نماد محاسبه می‌شود (نه یک درصد ثابت)؛ `STOP_LOSS_PERCENT` / `TAKE_PROFIT_PERCENT` فقط زمانی fallback می‌شوند که این محاسبه ممکن نباشد.
2. **مدار قطع ضرر روزانه** (`RiskManager`) — اگر مجموع ضرر تجمعی امروز (روی مجموع همه‌ی نمادها، پس از کسر کارمزد) از `MAX_DAILY_LOSS_PERCENT` عبور کند، ربات تا روز بعد پوزیشن جدید باز نمی‌کند (پوزیشن‌های باز موجود همچنان بر اساس حد ضررشان بسته می‌شوند).

⚠️ چون سقف دستی تعداد/مبلغ/تعداد روزانه دیگر وجود ندارد، مسئولیت اندازه‌ی کلی ریسک روی خودتان است: مقدار `QUOTE_ASSET` که در حساب تبدیل نگه می‌دارید عملا سقف واقعی سرمایه‌ای است که ربات می‌تواند در معرض ریسک بگذارد.

**وضعیت مدار قطع، در برابر ری‌استارت هم پایدار است:** تعداد معامله و سود/زیان تجمعی «امروز» که در `RiskManager` استفاده می‌شود، هر بار از `data/trade_history.jsonl` (که روی دیسک است، نه فقط حافظه) بازسازی می‌شود. بدون این، هر ری‌استارت پردازش (مثلا برای گرفتن آپدیت) یک شمارنده‌ی صفر تازه می‌ساخت و اگر مدار قطع قبل از آن فعال شده بود، بی‌سروصدا خاموشش می‌کرد — یعنی ربات دقیقا همان روزی که نباید، دوباره اجازه‌ی معامله پیدا می‌کرد. همچنین به همین دلیل، عدد «معاملات امروز» در کارت «وضعیت ربات» بعد از هر ری‌استارت درست باقی می‌ماند و به صفر برنمی‌گردد.

## اعلان آندرویدی برای رویدادهای مهم

چون ربات خودمختار اجرا می‌شود، لازم نیست دائم داشبورد را باز نگه دارید — ولی برای چند رویداد حیاتی که واقعا باید سریع بدانید، یک اعلان آندرویدی (نوتیفیکیشن) از طریق [Termux:API](https://f-droid.org/packages/com.termux.api/) می‌فرستد:

- ربات به‌خاطر خطای غیرمنتظره متوقف و خودش دوباره شروع شد (بخش «مقاومت در برابر کرش غیرمنتظره» بالاتر).
- مدار قطع ضرر روزانه فعال شد.
- پاسخ یک سفارش واقعی ساختار ناشناخته داشت و پوزیشن با تخمین محلی ثبت شد (دقیقا همان دسته باگی که باعث این قابلیت شد؛ این‌جا فوراً به شما اطلاع می‌دهد تا خودتان دستی موجودی واقعی را چک کنید، نه اینکه ساعت‌ها بعد از لاگ متوجه شوید).

فعال‌سازی (یک‌بار، اختیاری — بدون آن ربات عادی کار می‌کند، فقط اعلان نمی‌فرستد):

```bash
pkg install termux-api
```

و اپ **Termux:API** را هم از F-Droid (نه Google Play) نصب کنید. بعد از این، اعلان‌ها خودکار کار می‌کنند — نیازی به تنظیم دیگری در `.env` نیست.

## محدودیت‌های شناخته‌شده

- API تبدیل endpoint مشخصی برای کندل/OHLCV یا حجم ۲۴ ساعته در SDK رسمی ندارد؛ قیمت از `depth` (میانگین بهترین خرید/فروش) یا در صورت خطا از آخرین معامله (`trades`) خوانده می‌شود، و رتبه‌بندی «پرفعالیت‌ترین نمادها» هم یک تقریب بر اساس ارزش آخرین چند معامله است، نه حجم واقعی ۲۴ ساعته.
- اگر فیلد‌های واقعی `exchange_info` با فرض‌های `src/market_scanner.py` فرق داشته باشد (کلید نماد، quote asset، status)، کشف خودکار ممکن است لیست خالی یا نادرست برگرداند و به لیست پیش‌فرض (`BTC_IRT, ETH_IRT, USDT_IRT`) سقوط کند — حتما اول با `scripts/inspect_api.py` بررسی کنید.
- استراتژی پیش‌فرض ساده است و برای معاملات واقعی باید بک‌تست و تنظیم شود.
- این پروژه backtest ندارد؛ قبل از اجرای واقعی، منطق استراتژی را جداگانه روی داده تاریخی محک بزنید.
- برای سرعت، قیمت نمادهای هر چرخه (`TradingBot.PRICE_FETCH_WORKERS`) و رتبه‌بندی فعالیت نمادها موقع بروزرسانی watchlist (`market_scanner.ACTIVITY_FETCH_WORKERS`) هم‌زمان با چند ترد خوانده می‌شوند، نه یکی‌یکی. با این حال چون هر نماد همچنان یک درخواست شبکه‌ای جداست، تعداد نماد watchlist دستی نیست و به یک سقف ثابت (`DEFAULT_WATCHLIST_SIZE` در `src/market_scanner.py`) محدود شده تا یک چرخه کامل بیشتر از `POLL_INTERVAL_SECONDS` طول نکشد.
- `TRADING_FEE_PERCENT` پیش‌فرض (۰.۳۵٪) یک تخمین رایج است، نه نرخ تایید‌شده از تبدیل — حتما از داشبورد تبدیل نرخ واقعی حساب خودتان را بگیرید.
- فیلتر خبر فقط برای کوین‌های شناخته‌شده در CryptoCompare داده معناداری دارد؛ برای نمادهای کم‌شناخته یا سهام توکنایز‌شده (مثل `GOOGLX_IRT`) معمولا نتیجه‌ای پیدا نمی‌کند و خنثی می‌ماند. بدون کلید هم کار می‌کند ولی محدودیت نرخ IP به‌مرور کمتر می‌شود.
- درصد `IRT` روی تبدیل معادل «تومان» گرفته شده (مطابق قرارداد رایج صرافی‌های ایرانی)، نه ریال؛ اگر این فرض اشتباه بود، فرمت نمایش قیمت در `webapp/templates/index.html` (تابع `fmtToman`) را اصلاح کنید.
