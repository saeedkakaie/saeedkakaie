# ربات معامله‌گر خودکار صرافی تبدیل

یک ربات پایتونی برای اجرای خودکار استراتژی نوسان‌گیری روی [صرافی تبدیل](https://www.tabdeal.org/) با استفاده از SDK رسمی `tabdeal-python`. ربات نیازی به معرفی دستی نماد ندارد: خودش پرفعالیت‌ترین نمادهای بازار را کشف می‌کند و می‌تواند هم‌زمان روی چند نماد پوزیشن باز داشته باشد.

## ⚠️ هشدار مهم قبل از هر چیز

- **این توصیه مالی نیست.** معامله‌ی خودکار ارز دیجیتال ریسک از دست دادن سرمایه دارد و هیچ استراتژی سودآوری تضمینی ندارد.
- **همیشه اول با `DRY_RUN=true`** (حالت پیش‌فرض) اجرا کنید تا رفتار ربات را روی داده واقعی بازار، بدون ثبت سفارش واقعی، ببینید.
- وقتی به حالت واقعی (`DRY_RUN=false`) رفتید، با **کمترین مبلغ ممکن** شروع کنید.
- کلید API را طوری بسازید که:
  - فقط دسترسی **spot trading** داشته باشد.
  - دسترسی **withdrawal (برداشت)** را **غیرفعال** کنید.
  - اگر صرافی امکان محدودسازی IP را می‌دهد، فعال کنید.
- فایل `.env` را **هرگز** commit یا در جایی به اشتراک نگذارید — شامل کلید و رمز API شماست.

## قبل از اجرا: بررسی API با داده واقعی

چون ساختار دقیق پاسخ‌های API تبدیل در مستندات پشت لاگین قرار دارد (docs.tabdeal.org)، قبل از اعتماد به ربات این اسکریپت را اجرا کنید تا مطمئن شوید فرضیات کد (ساختار order book، موجودی حساب، دقت اعشار مقدار سفارش) با پاسخ واقعی هم‌خوانی دارد:

```bash
python scripts/inspect_api.py
```

خروجی را با دقت بررسی کنید، به‌خصوص:
- `exchange_info` برای مطمئن شدن که ساختار فرض‌شده در `src/market_scanner.py` (کلیدهای `tabdealSymbol`/`symbol`، `quoteAsset`، `status`) با پاسخ واقعی هم‌خوانی دارد — و برای پیدا کردن دقت اعشار مجاز (`QUANTITY_PRECISION`) و حداقل مقدار سفارش هر نماد.
- بخش «کشف خودکار watchlist» که نشان می‌دهد ربات با تنظیمات فعلی چه نمادهایی را انتخاب می‌کند.
- `account` برای مطمئن شدن که نام دارایی‌ها (`asset`) با آنچه در `exchange_client.py` فرض شده مطابقت دارد.

## تنظیمات (.env)

| متغیر | توضیح |
|---|---|
| `TABDEAL_API_KEY` / `TABDEAL_API_SECRET` | کلید API (فقط برای حالت واقعی لازم است) |
| `QUOTE_ASSET` | دارایی مبنای بازاری که ربات باید در آن نماد پرفعالیت پیدا کند، مثل `IRT` |
| `WATCHLIST_SIZE` | چند نماد پرفعالیت هم‌زمان زیر نظر گرفته شود |
| `WATCHLIST_REFRESH_MINUTES` | هر چند دقیقه یک‌بار لیست نمادهای پرفعالیت دوباره محاسبه شود |
| `MAX_CONCURRENT_POSITIONS` | حداکثر تعداد پوزیشن باز هم‌زمان (سرمایه درگیر = این عدد × `QUOTE_ORDER_AMOUNT`) |
| `QUOTE_ORDER_AMOUNT` | مبلغ هر معامله بر حسب دارایی quote |
| `QUANTITY_PRECISION` | دقت اعشار پیش‌فرض (fallback)؛ ربات برای هر نماد جداگانه سعی می‌کند دقت واقعی را خودش از exchange_info بخواند (پایین‌تر توضیح داده شده) |
| `TRADING_FEE_PERCENT` | کارمزد هر پای معامله به درصد؛ در محاسبه سود/زیان دو برابرش (خرید+فروش) کم می‌شود. نرخ واقعی حساب خودتان را از تبدیل بگیرید |
| `STOP_LOSS_PERCENT` / `TAKE_PROFIT_PERCENT` | فقط وقتی استراتژی نتواند حد ضرر/سود پویا محاسبه کند استفاده می‌شوند (fallback) |
| `MAX_DAILY_LOSS_PERCENT` | سقف ضرر تجمعی روزانه (روی مجموع همه‌ی نمادها، پس از کسر کارمزد)؛ با عبور از آن ربات پوزیشن جدید باز نمی‌کند تا فردا |
| `MAX_TRADES_PER_DAY` | حداکثر تعداد معامله کامل (خرید+فروش) در روز، روی مجموع همه‌ی نمادها |
| `SMA_FAST_PERIOD` / `SMA_SLOW_PERIOD` | فقط برای استراتژی جایگزین `SmaCrossoverStrategy` استفاده می‌شوند |
| `NEWS_ENABLED` / `NEWS_API_KEY` / `NEWS_CACHE_MINUTES` | فیلتر سبک اخبار (اختیاری، `NEWS_API_KEY` هم اختیاری) — پایین‌تر توضیح داده شده |
| `POLL_INTERVAL_SECONDS` | فاصله بررسی قیمت هر نماد (ثانیه) |
| `DRY_RUN` | `true` = فقط شبیه‌سازی، هیچ سفارش واقعی ثبت نمی‌شود |

## اجرا (داشبورد وب محلی)

راه دیگر اجرا، داشبورد تحت وب است که فقط روی سیستم خودتان (`127.0.0.1`) بالا می‌آید — نه یک سایت عمومی. از اونجا می‌تونید کلید API، تنظیمات ریسک و استراتژی رو وارد کنید، ربات رو Start/Stop کنید، و این‌ها رو ببینید:
- جدول لحظه‌ای هر نماد: قیمت (به تومان با جداکننده هزارگان)، سیگنال (رنگی: سبز=BUY، قرمز=SELL، خاکستری=HOLD)، پوزیشن باز، هدف فروش/حد ضرر، و سود/زیان (درصد + مبلغ، پس از کارمزد).
- کارت «موجودی حساب» با دکمه بروزرسانی — موجودی هر دارایی را جدا از تبدیل می‌خواند.
- کارت «عملکرد معاملات» با آمار امروز/این‌ماه/امسال.
- لاگ زنده.

```bash
cd tabdeal-trading-bot
source venv/bin/activate   # اگر venv نساختید، طبق بخش نصب بسازید
python webapp/app.py
```

روی گوشی با Termux، به‌جای دستور بالا از `run.sh` استفاده کنید — این اسکریپت قبل از بالا آوردن سرور خودش `termux-wake-lock` را هم فعال می‌کند تا اندروید وسط کار ربات را نکشد:

```bash
bash run.sh
```

بعد در مرورگر خودتان (همون سیستمی که دستور رو زدید) به آدرس زیر برید:

```
http://127.0.0.1:5000
```

### ⚠️ هشدار امنیتی مهم درباره‌ی داشبورد وب

- این سرور **فقط روی 127.0.0.1** (لوکال‌هاست) اجرا می‌شود و از بیرون سیستم شما در دسترس نیست. **هرگز** `host="127.0.0.1"` را در `webapp/app.py` به `0.0.0.0` تغییر ندهید یا این پورت را روی اینترنت/شبکه باز نکنید، مگر اینکه احراز هویت (login) و HTTPS واقعی اضافه کنید — وگرنه هرکسی که به این آدرس برسد می‌تواند کلید API و پول شما را کنترل کند.
- کلید API فقط در فایل `.env` روی همان سیستم ذخیره می‌شود و هیچ‌وقت به مرورگر یا جای دیگری ارسال نمی‌شود.
- این سرور توسعه‌ای Flask است (نه production-grade) و فقط برای استفاده‌ی شخصی و محلی طراحی شده.

## استراتژی پیش‌فرض: TechnicalStrategy

استراتژی پیش‌فرض (`TechnicalStrategy` در `src/strategy.py`) پنج اندیکاتور تکنیکال را ترکیب می‌کند و فقط وقتی اکثریت هم‌جهت باشند سیگنال می‌دهد:

- **RSI** (اشباع خرید/فروش)
- **MACD** (شتاب روند)
- **باند بولینگر** (نزدیکی قیمت به کف/سقف نوسان اخیر)
- **Stochastic Oscillator**
- **روند EMA بلندمدت** (فیلتر جهت کلی بازار)

هر اندیکاتور یک رأی ۱-/۰/۱+ می‌دهد؛ فقط با عبور مجموع رأی‌ها از آستانه (پیش‌فرض ۳ از ۵) و فقط روی همان لحظه‌ی عبور (نه هر تیک) سیگنال BUY/SELL صادر می‌شود.

**حد ضرر/سود پویا:** چون API تبدیل کندل نمی‌دهد و ATR واقعی در دسترس نیست، حد ضرر/سود هر پوزیشن از نوسان اخیر قیمت (انحراف معیار بازده‌ها) محاسبه می‌شود — نه یک درصد ثابت. این عدد در لحظه‌ی باز شدن پوزیشن قفل می‌شود و در لاگ و داشبورد («هدف فروش / حد ضرر») نمایش داده می‌شود، یعنی همون لحظه‌ی خرید می‌دونید تا چه قیمتی نگه دارید و در چه قیمتی می‌فروشد.

**فیلتر خبر (اختیاری):** اگر `NEWS_ENABLED=true` باشد، ربات قبل از هر خرید عنوان آخرین اخبار همان کوین را از endpoint عمومی و رایگان [CryptoCompare](https://min-api.cryptocompare.com/data/v2/news/) می‌خواند — **بدون نیاز به ثبت‌نام یا کلید**. عنوان‌ها با چند کلیدواژه‌ی ساده (مثل hack/lawsuit در برابر partnership/listing) امتیازدهی می‌شوند. خبر بسیار منفی جلوی خرید را می‌گیرد؛ خبر بسیار مثبت آستانه‌ی خرید را کمی پایین می‌آورد. فروش هیچ‌وقت به‌خاطر خبر متوقف نمی‌شود (مدیریت ریسک همیشه باید بتواند پوزیشن را ببندد). اگر بعدا خواستید محدودیت نرخ بالاتری داشته باشید، یک کلید اختیاری از [cryptocompare.com](https://www.cryptocompare.com/cryptopian/api-keys) در `NEWS_API_KEY` بگذارید — کاملا اختیاری است.

⚠️ این استراتژی هم یک نمونه‌ی معقول برای شروع است، نه توصیه‌ی مالی و نه تضمین سود. حتما قبل از استفاده‌ی واقعی رفتارش را در DRY_RUN زیر نظر بگیرید.

برای جایگزینی با استراتژی خودتان:
1. در `src/strategy.py` کلاسی بسازید که از `Strategy` ارث‌بری کند و متد `update(self, price: float) -> Signal` را پیاده‌سازی کند (و اختیاری: `suggested_risk_levels()` برای حد ضرر/سود پویا).
2. در `main.py` (و `webapp/bot_runner.py` اگر از داشبورد وب استفاده می‌کنید) تابع `strategy_factory(symbol)` را طوری تغییر دهید که کلاس خودتان را برگرداند. هر نماد یک نمونه‌ی جداگانه از استراتژی می‌گیرد، بنابراین state هر نماد از نمادهای دیگر جدا می‌ماند.

## کارمزد و عملکرد معاملات

- `TRADING_FEE_PERCENT` نرخ کارمزد هر پای معامله است؛ در محاسبه‌ی سود/زیان هر پوزیشن، دو برابر این عدد (خرید + فروش) از سود خام کم می‌شود — هم در نمایش زنده‌ی پوزیشن باز، هم در ثبت نهایی معامله.
- هر معامله‌ی بسته‌شده در `data/trade_history.jsonl` ثبت می‌شود (این فایل شخصی‌ست و در `.gitignore` قرار دارد، commit نمی‌شود).
- داشبورد وب کارت «عملکرد معاملات» را نشان می‌دهد: تعداد معامله، درصد و مبلغ سود/زیان برای امروز، این ماه و امسال.
- ⚠️ این درصدها **مجموع ساده‌ی درصد سود/زیان هر معامله** در آن دوره است، نه بازده مرکب یا وزن‌دار سرمایه (مثل بازده واقعی پرتفوی). برای یک ابزار شخصی سبک کافی است ولی معادل محاسبات دقیق مالی نیست.

## کشف خودکار نماد و چند پوزیشن هم‌زمان

به‌جای این‌که یک نماد ثابت به ربات بدهید، ربات در `src/market_scanner.py`:
1. لیست همه‌ی نمادهای فعال بازار را از `exchange_info` می‌گیرد و بر اساس `QUOTE_ASSET` (مثلا `IRT`) فیلتر می‌کند.
2. بر اساس ارزش آخرین معاملات هر نماد (تقریبی از فعالیت/نقدشوندگی، چون endpoint حجم ۲۴ ساعته در SDK رسمی موجود نیست) پرفعالیت‌ترین‌ها را رتبه‌بندی می‌کند.
3. بالاترین `WATCHLIST_SIZE` نماد را انتخاب و هر `WATCHLIST_REFRESH_MINUTES` دقیقه این لیست را دوباره محاسبه می‌کند.

سپس ربات هم‌زمان روی چند نماد از این لیست پوزیشن باز می‌کند (تا سقف `MAX_CONCURRENT_POSITIONS`). اگر نمادی از لیست خودکار خارج شود ولی پوزیشن باز روی آن دارید، ربات همچنان آن پوزیشن را تا بسته‌شدن (با حد ضرر/سود یا سیگنال فروش) دنبال می‌کند — پوزیشن باز هرگز رها نمی‌شود.

⚠️ **نکته سرمایه:** حداکثر سرمایه‌ای که می‌تواند هم‌زمان درگیر شود تقریبا برابر است با `MAX_CONCURRENT_POSITIONS × QUOTE_ORDER_AMOUNT`. این عدد را متناسب با موجودی واقعی‌تان تنظیم کنید.

### دقت اعشار مقدار سفارش، جداگانه برای هر نماد

هر بار که watchlist بروزرسانی می‌شود، ربات با `fetch_quantity_precisions` (در `src/market_scanner.py`) تلاش می‌کند دقت اعشار مجاز مقدار (quantity) **هر نماد را جداگانه** از `exchange_info` استخراج کند (اول فیلدهای مستقیم مثل `baseAssetPrecision`، بعد `stepSize` داخل فیلتر `LOT_SIZE`). اگر برای نمادی پیدا نشود، از `QUANTITY_PRECISION` به‌عنوان مقدار پیش‌فرض همان یک نماد استفاده می‌شود — نه اینکه یک عدد ثابت به‌زور روی همه‌ی نمادها اعمال شود. برای دیدن دقیقاً چه عددی برای هر کوین در watchlist فعلی‌تان محاسبه شده:

```bash
python scripts/inspect_api.py
```

## پایداری پوزیشن‌های باز در برابر ری‌استارت

پوزیشن‌های باز در `data/open_positions.json` ذخیره می‌شوند و با هر شروع ربات دوباره خوانده می‌شوند. این برای این است که اگر پردازش به هر دلیل (آپدیت کد، ری‌استارت گوشی، کشته‌شدن Termux توسط اندروید) دوباره اجرا شود، ربات پوزیشن‌های واقعاً بازش را فراموش نکند — وگرنه هم حد ضرر/سود آن پوزیشن‌ها دیگر چک نمی‌شود، هم `MAX_CONCURRENT_POSITIONS` دیگر تعداد واقعی را نمی‌داند و اجازه می‌دهد بیشتر از سقف مجاز خرید انجام شود.

⚠️ **این فقط پوزیشن‌هایی را دنبال می‌کند که خودِ ربات (بعد از این نسخه) باز کرده باشد.** اگر قبل از این تغییر، به‌خاطر همین باگ چند بار ری‌استارت شده و چند دارایی مختلف خریده باشید، آن‌ها در `data/open_positions.json` ثبت نشده‌اند و ربات حد ضرر/سودی برایشان چک نمی‌کند. باید خودتان از اپ تبدیل تصمیم بگیرید با آن‌ها چیکار کنید (نگه‌داشتن دستی یا فروش دستی)؛ ربات به‌صورت خودکار آن‌ها را نمی‌فروشد یا «قبضه» نمی‌کند.

## مدیریت ریسک

`RiskManager` سه لایه محافظت دارد (روی مجموع همه‌ی نمادها، نه هرکدام جدا):
1. **حد ضرر/سود روی هر پوزیشن** — بر اساس `STOP_LOSS_PERCENT` / `TAKE_PROFIT_PERCENT`.
2. **سقف تعداد معامله روزانه** — از رفتار بیش‌فعال ربات در بازارهای پرنوسان جلوگیری می‌کند.
3. **مدار قطع ضرر روزانه** — اگر مجموع ضرر روزانه از `MAX_DAILY_LOSS_PERCENT` عبور کند، ربات تا روز بعد پوزیشن جدید باز نمی‌کند (پوزیشن‌های باز موجود همچنان بر اساس حد ضررشان بسته می‌شوند).

به این‌ها `MAX_CONCURRENT_POSITIONS` هم اضافه می‌شود که مستقیما در `bot.py` سقف تعداد پوزیشن هم‌زمان را کنترل می‌کند.

## تست

```bash
pip install -r requirements-dev.txt

```

## محدودیت‌های شناخته‌شده

- API تبدیل endpoint مشخصی برای کندل/OHLCV یا حجم ۲۴ ساعته در SDK رسمی ندارد؛ قیمت از `depth` (میانگین بهترین خرید/فروش) یا در صورت خطا از آخرین معامله (`trades`) خوانده می‌شود، و رتبه‌بندی «پرفعالیت‌ترین نمادها» هم یک تقریب بر اساس ارزش آخرین چند معامله است، نه حجم واقعی ۲۴ ساعته.
- اگر فیلد‌های واقعی `exchange_info` با فرض‌های `src/market_scanner.py` فرق داشته باشد (کلید نماد، quote asset، status)، کشف خودکار ممکن است لیست خالی یا نادرست برگرداند و به لیست پیش‌فرض (`BTC_IRT, ETH_IRT, USDT_IRT`) سقوط کند — حتما اول با `scripts/inspect_api.py` بررسی کنید.
- استراتژی پیش‌فرض ساده است و برای معاملات واقعی باید بک‌تست و تنظیم شود.
- این پروژه backtest ندارد؛ قبل از اجرای واقعی، منطق استراتژی را جداگانه روی داده تاریخی محک بزنید.
- بررسی سیگنال چند نماد در هر چرخه به‌صورت متوالی (نه موازی) انجام می‌شود؛ اگر `WATCHLIST_SIZE` را خیلی زیاد کنید، ممکن است یک چرخه کامل بیشتر از `POLL_INTERVAL_SECONDS` طول بکشد.
- `TRADING_FEE_PERCENT` پیش‌فرض (۰.۳۵٪) یک تخمین رایج است، نه نرخ تایید‌شده از تبدیل — حتما از داشبورد تبدیل نرخ واقعی حساب خودتان را بگیرید.
- فیلتر خبر فقط برای کوین‌های شناخته‌شده در CryptoCompare داده معناداری دارد؛ برای نمادهای کم‌شناخته یا سهام توکنایز‌شده (مثل `GOOGLX_IRT`) معمولا نتیجه‌ای پیدا نمی‌کند و خنثی می‌ماند. بدون کلید هم کار می‌کند ولی محدودیت نرخ IP به‌مرور کمتر می‌شود.
- درصد `IRT` روی تبدیل معادل «تومان» گرفته شده (مطابق قرارداد رایج صرافی‌های ایرانی)، نه ریال؛ اگر این فرض اشتباه بود، فرمت نمایش قیمت در `webapp/templates/index.html` (تابع `fmtToman`) را اصلاح کنید.
