# سامانه کدینگ استاندارد کالا و حاکمیت داده‌ی زنجیره تامین

نسخه‌ی نمایشی/توسعه — پیاده‌سازی کامل معماری پیشنهادی سند فنی پروژه (پاکسازی بانک کالا + منطق تعریف کد جدید).

## دو بخش اصلی

### ۱) پاکسازی بانک کالای فعلی (`/legacy`)
بانک کالای فعلی (اکسل خروجی SAP یا مشابه) بارگذاری می‌شود و موتور تحلیل — دقیقاً همان الگوریتم‌های تایید‌شده‌ی
`پاکسازی_بانک_کالا.py` اصلی (اکنون در `backend/cleanup_engine.py`) — موارد زیر را شناسایی می‌کند:
- تکرار دقیق و تکرار «فرمتی/نرم» (با حفظ نقطه‌ی اعشاری معنادار مثل ۱.۱kw در برابر ۱۱kw)
- ناهماهنگی گروه و واحد اندازه‌گیری بین پلنت‌ها
- خرابی نقل‌قول، کاما‌ی اعشاری اشتباه، حروف عربی/ارقام غیراستاندارد
- **علاوه بر یافته‌های اصلی**: تطابق هر ردیف با ۱۰ قاعده‌ی نگارش استاندارد جدید (نه فقط تکرار) — یعنی حتی کدهای
  یکتا (بدون تکرار) که با قاعده‌ی جدید همخوانی ندارند هم شناسایی و علامت‌گذاری می‌شوند.

خروجی: گزارش داخل سامانه + فایل اکسل قابل دانلود با شیت‌های خلاصه/خوشه‌ها/داده‌ی کامل/ناسازگارها.

### ۲) منطق تعریف کد جدید (`/materials/new`)
ثبت کالای جدید کاملاً بدون تایپ آزاد:

1. **طبقه‌بندی آبشاری**: گروه (۱۸ گروه استاندارد و قفل‌شده) → نوع کالا → ویژگی‌های ثابت آن نوع کالا — همه Picklist.
2. **شرح خودکار**: از ترکیب مقادیر انتخابی ساخته می‌شود؛ کاربر هرگز شرح را تایپ نمی‌کند.
3. **گیت جستجوی تکرار** (زنده، حین تایپ نبودن انتخاب‌ها): تطبیق فازی (rapidfuzz) شرح تولیدشده با
   کالاهای فعال/در جریان و بانک Legacy هم‌گروه — آستانه‌ی هشدار ۷۲٪ / مسدودسازی ۹۰٪.
4. **کد**: سریالی و بی‌معنا، فقط بعد از عبور کامل از گردش تایید صادر می‌شود (بازه‌ی عددی هر گروه در
   `MaterialGroup.number_range_prefix`، هم‌راستا با الگوی موجود در داده‌ی واقعی هلدینگ).
5. **گردش تایید ۴+۱ مرحله‌ای**: گیت تکرار (خودکار) → فنی → بازرگانی → MRP → حاکمیت داده (صدور نهایی کد).
6. **درخواست مقدار جدید**: اگر مقدار مناسبی در فهرست یک ویژگی نبود، به‌جای تایپ، کاربر «درخواست افزودن»
   ثبت می‌کند؛ فقط نقش «حاکمیت داده» (از `/classification`) مقدار جدید را به کاتالوگ اضافه می‌کند.

### دیتاشیت خرید و ماتریس کرالجیک
هر کالا یک دیتاشیت خرید دارد (سازنده، برند، مدل کاتالوگ، مبدا، Incoterm، بازه‌ی زمان تحویل/قیمت، MOQ،
تامین‌کنندگان پیشنهادی) و یک ارزیابی کرالجیک (ریسک تامین × تاثیر بر هزینه/سود) که استراتژی خرید
(استراتژیک/اهرمی/گلوگاهی/عمومی) را خودکار محاسبه می‌کند. نمای تجمیعی در `/kraljic`.

## اجرا

```bash
cd app
pip install -r requirements.txt
./run.sh          # پیش‌فرض روی پورت 8000؛ با PORT=8080 ./run.sh قابل تغییر است
```

بذرپاشی اولیه (۱۸ گروه، پلنت‌های هلدینگ، واحدها، قالب ویژگی ۱۸ گروه، کاربران نمونه) در اولین اجرا خودکار
انجام می‌شود. برای بازنشانی کامل: `rm app/data/material_coding.db && python3 app/backend/seed.py`

پایگاه‌داده فعلاً SQLite است (فایل `app/data/material_coding.db`) — برای انتقال به سرور اصلی فقط کافی‌ست
`DATABASE_URL`/`database.py` به Postgres تغییر کند؛ کل منطق (SQLAlchemy ORM) بدون تغییر باقی می‌ماند.

## نکات برای انتقال به سرور اصلی

- **نقش‌ها/احراز هویت**: فعلاً «کاربر جاری» از یک فهرست انتخاب می‌شود (بدون رمز عبور) — قبل از استقرار نهایی
  باید به SSO/LDAP هلدینگ وصل شود.
- **قالب ویژگی**: فقط ۸ گروه پرحجم (مکانیک، برق و الکترونیک، لوله و اتصالات، ابزارآلات، شیمیایی، HSE،
  مواد اولیه غذایی، اموال ثابت) با عمق کامل تعریف شده‌اند طبق سند فنی؛ ۱۰ گروه باقی‌مانده یک قالب سبک
  اولیه دارند و باید با تیم حاکمیت داده تکمیل شوند (از `/classification`، بدون نیاز به کدنویسی).
  بذرپاشی کامل در `backend/seed.py` (متغیر `TEMPLATES`).
  همچنین اجرای واقعی مرحله‌ی «merge کردن ۶۹۹ کد تکراری تاریخی» و «بررسی دستی ۸۰ کد با ناهماهنگی واحد»
  (طبق سند فنی، بخش ۸) باید از طریق ماژول پاکسازی روی اکسپورت واقعی هلدینگ انجام شود؛ این سرور یک بانک
  Legacy نمونه (مصنوعی) برای دمو دارد که باید با اکسپورت واقعی جایگزین شود.
- **کد صدورشده**: بازه‌ی عددی هر گروه (`number_range_prefix`) با نمونه‌های واقعی هلدینگ هم‌راستا طراحی شده
  اما باید توسط تیم SAP/MDM قبل از استقرار نهایی تایید شود تا با بازه‌های موجود تداخل نکند.

## ساختار پروژه

```
app/
  backend/
    main.py            روت‌های صفحات + API
    models.py           مدل‌های دیتابیس
    schemas.py           مدل‌های ورودی API
    business.py          شرح خودکار، گیت تکرار، صدور کد، محاسبه کرالجیک
    cleanup_engine.py    موتور عارضه‌یابی (از اسکریپت اصلی استخراج‌شده)
    legacy_export.py    خروجی اکسل گزارش پاکسازی
    seed.py              داده‌ی اولیه
    sample_data.py       بانک کالای نمونه‌ی مصنوعی (فقط برای دمو)
  frontend/
    templates/           صفحات Jinja2 (RTL، فارسی)
    static/css/app.css   طراحی
  data/material_coding.db  دیتابیس SQLite
```
